# 5.3 Principais Componentes

Esta seção descreve os principais módulos do sistema, suas responsabilidades e como se relacionam entre si.

---

## Frontend

**Tecnologia:** React + React Flow

O frontend é uma Single Page Application (SPA) responsável por toda a interface de usuário. É organizado em módulos funcionais:

| Módulo | Responsabilidade |
|--------|-----------------|
| **Canvas (React Flow)** | Renderização dos elementos do diagrama, drag & drop, conexões entre nós e interação visual com o diagrama |
| **Editor Textual** | Interface de entrada de marcação estruturada (texto → canvas), com feedback de erros de sintaxe |
| **Sidebar de Elementos** | Exibe os elementos C4 disponíveis para o nível selecionado, ocultada quando nenhum nível está ativo |
| **Seletor de Nível C4** | Controle de alternância entre os quatro níveis do modelo (Contexto, Container, Componente, Código) |
| **Overlay de Sugestões** | Painel não obstrutivo que exibe sugestões da assistência inteligente, acionado pelo usuário |
| **Modal de Edição** | Formulário para edição das propriedades de um elemento (título, descrição, relacionamentos) |
| **Exportação** | Interface de seleção de formato e corte de imagem, com download iniciado no navegador |

---

## Backend API

**Tecnologia:** Node.js + Express

API REST organizada em camadas, responsável pela lógica de negócio, autenticação e orquestração das chamadas externas.

| Camada | Responsabilidade |
|--------|-----------------|
| **Routes** | Define e agrupa os endpoints, aplica middlewares de autenticação e validação |
| **Controllers** | Recebe as requisições, delega para os serviços e retorna as respostas |
| **Services** | Contém a lógica de negócio — validação C4, regras de domínio e orquestração |
| **Repositories** | Abstrai o acesso ao banco de dados, isolando as queries SQL e jsonb |
| **Middlewares** | Autenticação JWT, tratamento de erros e validação de entrada |

## Motor de Validação C4

**Localização:** Backend — Diagram Service

Componente central da proposta do projeto. Responsável por verificar a consistência estrutural dos diagramas em relação às regras do modelo C4, conforme [RN07](../capitulo-2/2.5-regras-de-negocio.md) e [RN08](../capitulo-2/2.5-regras-de-negocio.md).

**Responsabilidades:**
- Verificar se os elementos adicionados são compatíveis com o nível C4 selecionado
- Validar conexões entre elementos do mesmo nível
- Sinalizar inconsistências em tempo real sem bloquear o fluxo de edição
- Conferir a coerência entre os níveis: os elementos ao redor devem ser os mesmos do nível de cima, e cada nível deve indicar qual elemento detalha quando houver mais de um candidato

---

## Ligação entre Níveis

**Localização:** Frontend — Editor de Diagramas

No C4, cada nível dá zoom em um elemento do nível de cima: o de Containers mostra o que existe dentro de um Sistema de Software do Contexto, e o de Componentes, o que existe dentro de um Container. Esse elemento é o **foco** do nível, um por nível, conforme [RN06](../capitulo-2/2.5-regras-de-negocio.md).

**Responsabilidades:**
- Definir o foco automaticamente quando há um único candidato; com mais de um, a escolha é feita no modal do elemento do nível de cima ("Detalhar"), que explica a troca quando o nível já detalha outro elemento
- Desenhar a **fronteira tracejada** da notação C4 em volta dos elementos de dentro, acompanhando-os quando se movem
- Mostrar no modal do elemento de qual elemento ele faz parte e em qual nível é detalhado

## Serviço de Assistência Inteligente

**Localização:** Backend — AI Service

Abstração da chamada à API de IA, isolada em um serviço dedicado (provedor separado da orquestração) para facilitar a troca de provider no futuro. As sugestões são **sempre pedidas pelo usuário** e **nunca aplicadas no diagrama**: a ferramenta é didática, a IA orienta e quem constrói é o usuário ([RN12](../capitulo-2/2.5-regras-de-negocio.md)).

**Responsabilidades:**
- Receber o contexto do projeto e do nível aberto (com um resumo dos outros níveis e do que o motor de validação já apontou), sem dados pessoais
- Pedir as sugestões ao **Claude Haiku**, em JSON num formato fechado (*structured outputs*)
- Conferir cada sugestão no **motor de validação C4** (RF17), aplicando-a numa cópia do diagrama em memória: são descartadas as que quebram RN08, repetem uma relação, citam um elemento inexistente ou duplicam um que já existe
- **Escalar uma única vez para o Claude Opus** quando a resposta do Haiku vem fraca (recusa, resposta cortada, instabilidade ou mais da metade descartada), e usar o Opus diretamente na "Análise aprofundada"
- Aplicar os limites diários por usuário e o teto de gasto diário do sistema, registrando o custo de cada chamada
- Ficar desligado, sem erro para o resto do sistema, enquanto não houver chave configurada

## Banco de Dados

**Tecnologia:** PostgreSQL

Responsável pela persistência de todos os dados do sistema. Utiliza modelo relacional para usuários e projetos, e colunas `jsonb` para o estado dos diagramas, conforme descrito na seção [5.2](5.2-modelo-de-dados.md).
