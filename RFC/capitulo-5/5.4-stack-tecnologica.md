# 5.4 Stack Tecnológica

Esta seção lista as tecnologias que compõem o sistema, com a justificativa de cada escolha.

---

## Frontend

| Tecnologia | Justificativa |
|------------|--------------|
| **React** | Biblioteca consolidada para construção de interfaces baseadas em componentes. Ecossistema amplo e familiaridade prévia da equipe |
| **React Flow** | Biblioteca especializada em canvas interativo com suporte nativo a drag & drop, conexões entre nós e renderização de grafos — caso de uso central da aplicação |

---

## Backend

| Tecnologia | Justificativa |
|------------|--------------|
| **Node.js** | Permite compartilhar o ecossistema JavaScript entre frontend e backend, reduzindo a curva de aprendizado e o contexto de troca durante o desenvolvimento |
| **Express** | Framework minimalista e flexível para Node.js, com ecossistema ativo e ampla adoção. Permite organização em camadas sem impor uma estrutura rígida |
| **JWT** | Padrão consolidado para autenticação stateless em APIs REST, compatível com a separação entre frontend e backend adotada na arquitetura |
| **bcrypt** | Algoritmo de hash com salt para armazenamento seguro de senhas, conforme definido no [RNF04](../capitulo-2/2.4-requisitos-nao-funcionais.md) |

---

## Banco de Dados

| Tecnologia | Justificativa |
|------------|--------------|
| **PostgreSQL** | Banco relacional robusto com suporte nativo a `jsonb`, permitindo armazenar o estado dos diagramas como documentos JSON sem necessidade de um banco NoSQL adicional. Familiaridade prévia e ampla documentação |

---

## Inteligência Artificial

| Tecnologia | Justificativa |
|------------|--------------|
| **Anthropic Claude API** (Claude Haiku e Claude Opus) | Respostas em JSON com formato garantido (*structured outputs*), o que permite conferir cada sugestão no motor de validação. O Haiku, de custo baixo, atende todo pedido; o Opus, mais capaz, só a escalada automática e a análise aprofundada, equilibrando custo e qualidade. Substituiu a Google Gemini API prevista na proposta original; a chamada é abstraída no AI Service, permitindo troca de provider com impacto mínimo |

---

## Hospedagem e Infraestrutura

| Tecnologia | Justificativa |
|------------|--------------|
| **Azure App Service** (Linux, container) | Executa a imagem Docker única (API + frontend compilado, mesma origem), publicada no GitHub Container Registry. Deploy contínuo pelo GitHub Actions com login OIDC, sem senha guardada, verificação da nova versão e reversão automática em caso de falha |
| **Azure Database for PostgreSQL — Flexible Server** | PostgreSQL gerenciado, com criptografia em repouso por padrão e TLS obrigatório; acesso liberado só aos endereços do App Service |
| **New Relic** (plano gratuito) | Monitoramento da aplicação em produção (tempo de resposta, erros e disponibilidade) |
| **Domínio próprio** (`c4diagrams.com.br`, Registro.br) | Endereço público da aplicação, com certificado TLS gerenciado pelo App Service (gratuito e renovado automaticamente) e redirecionamento de HTTP para HTTPS |
| **Resend** | Entrega dos e-mails de confirmação de cadastro e de redefinição de senha, pelo subdomínio verificado `mail.c4diagrams.com.br` (DKIM, SPF e DMARC) |

> **Nota:** a proposta original previa GitHub Pages e Railway. A hospedagem foi revista porque as regras da disciplina vedam o GitHub Pages e desaconselham plataformas como o Railway, e a assinatura Azure for Students cobre os recursos acima.
