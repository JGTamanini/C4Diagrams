# 2.4 Requisitos Não Funcionais (RNFs)

Esta seção cobre os requisitos relacionados à qualidade e usabilidade que o sistema busca atender, sendo independentes de funcionalidades específicas.

---

## 2.4.1 Desempenho

| ID | Requisito |
|----|-----------|
| RNF01 | O tempo de resposta para operações de edição do diagrama (adição, movimentação e conexão de elementos) deve ser inferior a **200ms** |
| RNF02 | O sistema deve renderizar diagramas com até **50 elementos** de forma fluida, sem degradação perceptível de performance |
| RNF03 | As sugestões e validações automáticas da assistência inteligente devem ser apresentadas em até **1 segundo** após a ação que as disparou |

---

## 2.4.2 Segurança

| ID | Requisito |
|----|-----------|
| RNF04 | O sistema deve utilizar autenticação segura baseada em tokens **JWT**, com senhas armazenadas utilizando hash e salt por meio de algoritmo adequado (ex: bcrypt) |
| RNF05 | O sistema deve garantir o **isolamento completo entre os dados dos usuários**, assegurando que nenhum usuário possa acessar, visualizar ou modificar projetos e diagramas pertencentes a outro |
| RNF06 | Os dados dos usuários, incluindo projetos e diagramas, devem ser armazenados de forma **criptografada em repouso** (encryption at rest) |

---

## 2.4.3 Disponibilidade

| ID | Requisito |
|----|-----------|
| RNF07 | O sistema deve estar disponível pelo menos **95% do tempo** em ambiente de produção, considerando o período a partir da disponibilização do MVP |
| RNF08 | O sistema deve realizar **salvamento automático** do progresso do diagrama a intervalos regulares, prevenindo perda de dados em caso de interrupção inesperada |

---

## 2.4.4 Escalabilidade

| ID | Requisito |
|----|-----------|
| RNF09 | O sistema deve suportar um número adequado de usuários simultâneos sem degradação significativa de desempenho — o valor exato será definido após testes de carga realizados durante o desenvolvimento |
| RNF10 | A arquitetura do sistema deve permitir a adição de novos tipos de elementos e níveis de diagramação **sem necessidade de reestruturação do código base** |

---

## 2.4.5 Usabilidade

| ID | Requisito |
|----|-----------|
| RNF11 | A interface deve funcionar adequadamente em resoluções a partir de **1280×720px**, em navegadores como Google Chrome, Mozilla Firefox e Microsoft Edge em suas versões estáveis mais recentes |
| RNF12 | Um usuário sem experiência prévia com o modelo C4 deve ser capaz de criar um diagrama C4 básico em tempo razoável, utilizando os recursos disponibilizados pela ferramenta como guia e validação — o tempo de referência será definido após testes de usabilidade realizados durante o desenvolvimento |
| RNF13 | O sistema deve apresentar **mensagens de erro claras e orientadas à ação**, indicando ao usuário o que ocorreu e como proceder |
