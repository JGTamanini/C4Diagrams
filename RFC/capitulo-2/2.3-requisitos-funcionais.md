# 2.3 Requisitos Funcionais (RFs)
 
Os requisitos funcionais descrevem as funcionalidades que o sistema irá oferecer, levando em consideração as [personas](2.1-personas.md), os [casos de uso](2.2-casos-de-uso.md) identificados e as respostas obtidas nas pesquisas realizadas com usuários.
 
---
 
## 2.3.1 Autenticação
 
| ID | Requisito |
|----|-----------|
| RF01 | O sistema deve permitir o cadastro de usuários por meio de formulários com dados básicos |
| RF02 | O sistema deve permitir a autenticação de usuários por meio de credenciais válidas |
| RF03 | O sistema deve permitir recuperação de senhas |
 
---
 
## 2.3.2 Gerenciamento de Projetos
 
| ID | Requisito |
|----|-----------|
| RF04 | O sistema deve permitir a criação de novos projetos de diagramas |
| RF05 | O sistema deve permitir a edição de projetos existentes |
| RF06 | O sistema deve permitir a exclusão de projetos |
| RF07 | O sistema deve permitir a listagem e visualização dos projetos do usuário |
 
---
 
## 2.3.3 Diagramação
 
| ID | Requisito |
|----|-----------|
| RF08 | O sistema deve permitir a adição, edição e remoção de componentes do diagrama |
| RF09 | O sistema deve permitir a conexão entre os elementos do diagrama |
| RF10 | O sistema deve oferecer suporte à diagramação por meio de interface visual baseada em Drag & Drop |
| RF11 | O sistema deve permitir a organização visual dos elementos no espaço de trabalho |
 
---
 
## 2.3.4 Estrutura do Modelo C4
 
| ID | Requisito |
|----|-----------|
| RF12 | O sistema deve permitir a separação dos diagramas entre os 4 níveis de diagramação em C4 (Contexto, Container, Componente e Código) |
| RF13 | O sistema deve permitir a navegação entre os diferentes níveis do modelo C4 dentro de um projeto |
| RF14 | O sistema deve garantir que os elementos adicionados sejam compatíveis com o nível selecionado |
 
---
 
## 2.3.5 Apoio ao Usuário
 
| ID | Requisito |
|----|-----------|
| RF15 | O sistema deve fornecer um template básico para exemplificação da criação de um diagrama |
| RF16 | O sistema deve oferecer sugestões para auxiliar na construção do diagrama |
| RF17 | O sistema deve validar a estrutura do diagrama |
 
---
 
## 2.3.6 Exportação
 
| ID | Requisito |
|----|-----------|
| RF18 | O sistema deve permitir a exportação do diagrama em formatos comuns como PNG e PDF |
 
---
 
## 2.3.7 Funcionalidades Adicionais
 
| ID | Requisito |
|----|-----------|
| RF19 | O sistema deve permitir a criação de diagramas por meio de entrada textual estruturada em linguagem de marcação inspirada no PlantUML, convertendo o texto em elementos visuais no canvas (texto → canvas); a direção inversa, de canvas para texto, não é suportada |
| RF20 | O sistema deve apresentar uma interface intuitiva e de fácil utilização |
