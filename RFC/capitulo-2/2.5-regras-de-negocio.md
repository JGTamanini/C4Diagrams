# 2.5 Regras de Negócio

Esta seção define as regras que governam o comportamento do sistema, independentemente da interface ou tecnologia utilizada.

---

## 2.5.1 Acesso e Autenticação

| ID | Regra |
|----|-------|
| RN01 | Apenas usuários autenticados podem criar, editar, visualizar e excluir projetos e diagramas |
| RN02 | Um usuário só pode acessar projetos e diagramas criados por ele próprio |
| RN03 | A recuperação de senha exige confirmação por e-mail antes da alteração ser efetivada |

---

## 2.5.2 Gerenciamento de Projetos

| ID | Regra |
|----|-------|
| RN04 | Todo projeto deve ter obrigatoriamente um nome antes de ser salvo |
| RN05 | A exclusão de um projeto implica na exclusão permanente de todos os diagramas vinculados a ele |
| RN06 | Um projeto pode conter múltiplos diagramas, um para cada nível do modelo C4 |

---

## 2.5.3 Estrutura do Modelo C4

| ID | Regra |
|----|-------|
| RN07 | Todo diagrama pertence a exatamente um dos quatro níveis do modelo C4: Contexto, Container, Componente ou Código |
| RN08 | Cada nível do modelo C4 possui um conjunto restrito de elementos válidos, e o sistema deve impedir a adição de elementos incompatíveis com o nível selecionado |
| RN09 | Conexões entre elementos só são permitidas quando ambos os elementos pertencem ao mesmo nível do diagrama |
| RN10 | Todo diagrama deve conter ao menos um elemento para ser salvo |

---

## 2.5.4 Assistência e Validação

| ID | Regra |
|----|-------|
| RN11 | O sistema deve sinalizar inconsistências estruturais no diagrama em tempo real, sem bloquear o fluxo de edição do usuário |
| RN12 | Sugestões automáticas são apenas orientativas e não impedem o usuário de prosseguir com uma estrutura diferente da sugerida |
